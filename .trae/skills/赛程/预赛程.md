# 赛程（直播吧 NBA）

## 适用场景（何时调用）

- 用户要求获取/同步“直播吧（zhibo8）NBA 赛程”并写入 MySQL
- 用户提供或确认 league\_id=924、league=NBA，且需要按“当前年”动态拼 year

## 数据源与请求构造

### URL

- 基础 URL：`https://stats.qiumibao.com/shuju/public/index.php`
- 查询参数：
  - `year` 为动态值：默认取“当前年份”（YYYY）；若当前月份 < 9（10/11/12），则 `year = 当前年份-1`
  - `year` 为动态值：默认取“当前年份”（YYYY），如果当前时间的月份大于9月份，小于等于12，那么获取到的year要，
  - `type`=`赛程`，`tab`=`赛程`
  - `league_id`=`924`，`league`=`NBA`
  - `_t` 为当前时间戳（毫秒）

### Method

- `GET`

### Headers（按需使用）

- `accept: application/json, text/plain, */*`
- `origin: https://data.zhibo8.cc`
- `referer: https://data.zhibo8.cc/`
- `user-agent: (保持浏览器 UA)`

## 返回结构解析规则

### 预期返回（示意）

```json
{
  "name": "nba",
  "type": "match",
  "data": [
    {
      "title": "2025-06-26 周四",
      "list": [
        {
          "saishi_id": "1628363",
          "日期": "2025-06-26",
          "时间": "08:00",
          "homeId": "50001806",
          "guestId": "50001687",
          "is_finish": 1,
          "赛事": "选秀大会"
        }
      ]
    }
  ]
}
```

### 关键字段提取（必须）

- `title`：比赛日期来源。只保留 `yyyy-MM-dd`（从 `title` 的开头截取 10 位）
- `时间`：比赛开始时间（`HH:mm`）
- `saishi_id`：比赛 id
- `homeId`：主队球队 id
- `guestId`：客队球队 id
- `is_finish`：是否完赛（0/1）
- `赛事`：赛事名称（例如“选秀大会”）

### 解析流程（推荐）

1. 校验返回是否为 JSON 对象，且 `data` 为数组
2. 遍历 `data[]`：
   - 取 `day = title[:10]`，必须满足 `YYYY-MM-DD`
   - 遍历 `list[]`，逐条提取上述字段
3. 每条记录保留一份 `raw_json`（可选）用于追溯

## MySQL 落库要求

### 表不存在时必须先创建

- 表名：`nba_zhiboba_yj_gamelist`

请参考 [datebase.md](./datebase.md) 中关于 `nba_zhiboba_yj_gamelist` 的定义与设计（包含具体的 DDL 与字段类型说明）。

### Upsert 策略（必须幂等）

- 以 `saishi_id` 为唯一键
- 写入时使用 `INSERT ... ON DUPLICATE KEY UPDATE` 更新 `game_date/start_time/is_finish/event_name/raw_json`

## 与本项目目录的对接建议（调用点）

- 请求封装：优先使用 `app/utils/http/client.py` 的 `HttpClient.get_json()`
- 重试机制：沿用 `app/utils/crawler/retry.py` 的 `retryable()`
- DB 连接：使用 `app/core/database.py` 的 `engine` 或 `SessionLocal`
- 赛程解析模块：建议放在 `app/modules/nba_schedule/` 内（例如新增 zhiboba\_fetcher/service），并复用现有 `parse_schedule` 思路

## 参考实现步骤（执行顺序）

1. 计算 `year`：默认 `当前年份(YYYY)`；若 `当前月份 > 9`，则 `year = 当前年份 - 1`
2. 计算 `_t = 当前毫秒时间戳`
3. 发起 GET 请求（带 headers 与 params）获取 JSON
4. 解析 `data`，生成待落库记录列表
5. 确保表存在（执行 DDL）
6. 对每条记录执行 upsert

## 输出要求

- 返回“本次同步统计”：总天数、总场次、成功 upsert 数、解析失败数
- 失败必须给出最小可定位信息：year、\_t、失败条目的 saishi\_id（若可得）

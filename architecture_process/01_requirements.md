# 01 需求澄清（门禁：需求冻结）

## 输入
- 业务目标：NBA 赛程 + 直播文本 + 语义关系抽取
- 数据来源清单：官方/第三方接口、网页、缓存源（必须列出 URL/权限/频率）
- 质量要求：延迟、完整性、准确率、可用性

## 产物（必须交付）
- 需求说明：范围、边界、术语表、口径定义（例如“赛程”以开赛时间为准）
- 数据字典 V0：字段名、类型、单位、允许空、取值范围
- 非功能需求：QPS、并发、超时、重试上限、数据库容量预估
- 风险清单：反爬策略、接口变更、文本噪声、中文分词歧义
- NLP 约束：直播文本分词统一使用 PaddleNLP 2.7+ `Taskflow("word_segmentation", mode="accurate")`
- 词典约束：比赛级球员完整名、主表别名、别名表别名统一通过 `user_dict` 注入，保证球员姓名优先整体切分
- 性能约束：直播文本按页批量分词，避免逐条初始化模型导致的吞吐抖动

## 检查清单（通过才进入下一阶段）
- 所有关键术语有定义且无冲突
- 至少 1 个端到端用例可复述：采集 → 解析 → 入库 → 抽取 → 查询
- 给出“失败策略”：源站不可用/解析失败/入库失败时的处理规则
- 明确分词兼容策略：停用词过滤规则不变，TaskFlow 替换后输出口径保持一致，球员别名展示统一归一化为完整球员名称

# 架构设计严格流程（总览）

## 目标
- 以可验收的“产物”为中心推进：每一阶段都有明确输入/输出/门禁
- 以可演进为前提：FastAPI 接口层 + MySQL 数据层 + 采集/NLP/语义抽取模块化

## 阶段与门禁
1. 需求澄清（见 01）：范围、口径、数据源、质量指标、非功能约束
2. 领域/数据建模（见 02）：实体、关系、事件流、边界上下文
3. API 设计（见 03）：资源命名、版本策略、错误模型、鉴权与限流预留
4. 数据库设计（见 04）：表结构、索引、DDL/DML 管理、迁移策略
5. 采集与 NLP/语义流水线（见 05）：爬虫重试、解析、分词、语义关系抽取
6. 安全与可观测性（见 06）：日志、追踪、告警、审计、异常处理与降级
7. 交付与验收（见 07）：部署、回滚、验收用例、数据回放与压测

## 统一约束
- 所有接口/任务必须可追踪：请求级 correlation_id（预留）
- 所有入库数据必须可追溯：source、fetched_at、evidence_id
- 所有 SQL 必须版本化：DDL 与 DML 分目录管理，并由统一入口调用
